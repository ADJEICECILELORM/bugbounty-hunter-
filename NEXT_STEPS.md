## V3 — Controlled verification (status)

- ✅ `verification/verdict_checker.py` — the deterministic judge. `check_verdict(observation_data, claim)` returns `supported` / `refuted` / `inconclusive` plus machine-readable reason codes by recomputing the compared flags from the recorded numbers; a recorded flag is never trusted. Thin, malformed, or contradictory data fails closed to `inconclusive`, and a control claim can never be `supported`. Replayed offline against the real Part 1 lab evidence it reproduces the live run exactly: the claim pair → `supported` (`status_and_bytes_match`), the control pair → `inconclusive` (`control_discriminated`). Tests: `tests/test_verdict_checker.py`.
- ✅ `verification/verdict_integrity.py` — the binding between a verdict and what it judged. Each stored verdict carries a sha256 over its content bound to the evidence row id, its canonical evidence content, the hypothesis id, and the two recorded target URLs; `verify_verdict()` recomputes both that digest and the judgement (pure, reason-coded, and it never raises), `store_verdict()` refuses to write a row that fails the same check, and the promotion gate and the report loader both verify before consuming. Tests: `tests/test_verdict_integrity.py` — every binding is tampered with in turn (edited field, edited evidence, digest recomputed over the wrong evidence, another hypothesis, another target, missing or malformed digest).
- ✅ `verification/run_hypothesis_verification.py` — gated runner for a human-authored plan of `RequestPair`s. It validates the whole plan first, authorizes and pins every target in it before the first request (an out-of-scope target stops the run with nothing sent), probes every control pair before recording any claim, raises `SetupControlError` with nothing written when a control fails to discriminate, uses only the guarded `probe_lab_target()` transport, stores no request credentials, and `flush()`es without ever calling `commit()` or writing `Hypothesis.status`. A rolled-back session leaves no observation, verdict, or link behind. Tests: `tests/test_run_hypothesis_verification.py`.
- ✅ `verification/finding_promotion.py` — the human-only promotion gate, and the only module in the project that writes a hypothesis status or creates a `Finding`. It requires `approved_by`, an `unverified` hypothesis, at least one supported non-control verdict, and evidence owned by that hypothesis; it refuses any refuted verdict and any verdict whose integrity digest does not verify against its evidence, hypothesis, and target; it writes a `PromotionAudit` row; it never commits. Tests: `tests/test_finding_promotion.py`, including source guards for both exclusivity claims and for the boundary that no other verification module can import or call the gate.
- ✅ `verification/finding_report.py` — pure Markdown renderer (`collect_finding_context` + `render_finding_report`): local-lab banner, asset/finding metadata, reproduction steps, status/bytes/sha256 comparison, verdict table with reason codes, a recomputed verdict-integrity line, bounded impact wording, limitations, and approval trail. The context loader verifies every verdict against its evidence, hypothesis, and target first; the renderer then refuses to render without a supported verdict or evidence, and two renders of the same evidence are byte-identical. Tests: `tests/test_finding_report.py`.
- ✅ `scripts/render_finding_report.py` — the operator-run closing step, committed as `a26a0fe`. It opens the existing `lab_evidence_v3.db` **read-only** at the SQLite level (`mode=ro&uri=true`, never `init_db`, never `session.commit()`), loads a promoted `Finding` by id, and renders it through the pure `verification/finding_report.py` into `finding-<id>.md` (gitignored). It fails closed on a missing database, a missing finding, and a tampered/no-supported-verdict record, prints exactly what it read and wrote plus a before/after sha256 proving the database bytes are unchanged, and never imports `verification.finding_promotion` (so it cannot promote). Like the other lab scripts, the suite never executes it — only its pure gates are imported and tested. Tests: `tests/test_render_finding_report.py` (4 cases).
- ⚠️ **Human-gated end to end.** Nothing in V3 runs on a schedule, and a finding exists only after a named human calls `promote_to_finding()`. No report has been filed with any program; a report is a local Markdown string, not a submission — and the "reported" step is now closable deliberately via `scripts/render_finding_report.py`, which writes that string to a local `.md` file without touching the database. **verified ≠ approved ≠ reported** are three separate states with three separate writers (the verdict writer, the promotion gate, the pure report renderer) — see the lifecycle invariant in `ARCHITECTURE.md`.
- ⚠️ Verdicts are machine checks over recorded evidence — not exploit confirmation and not a severity assessment. A promoted finding means "the deterministic checker agreed, with a control that discriminated," nothing more.
- ✅ The existing `lab_evidence.db` opens unchanged with the three new tables (`verdicts`, `findings`, `promotion_audit`); no existing table or column was altered, so the Part 1 evidence stays valid. Verified on a `/tmp` copy. V3 was developed without touching the live DB: the schema check runs against a copy, and the live file's mtime and size are unchanged.

## Endpoint inventory (status)

- ✅ `verification/endpoint_inventory.py` — the pure, offline seed-path inventory. `SEED_PATHS` is a fixed 9-entry tuple a reviewer can read in full (`/`, `/robots.txt`, `/api`, `/rest`, `/login`, `/register`, `/swagger.json`, `/openapi.json`, `/.well-known/security.txt`); `seed_paths(base_url)` returns those paths as absolute URLs in seed order; `inventory_from_seeds(base_url, authorize)` returns only the URLs a caller-supplied `Callable[[str], bool]` approved, so `[]` when it approves nothing. A base must be an absolute `http(s)` URL with a host and no query or fragment, else `ValueError`; only trailing slashes are normalized, so no candidate has a doubled separator. Tests: `tests/test_endpoint_inventory.py` (36 cases).
- ✅ The offline guarantee is **structural, not behavioral**: the tests parse the module with `ast` and assert its imports are exactly `__future__`, `collections.abc` and `urllib.parse`, that its only module-level functions are `_normalized_base`, `seed_paths` and `inventory_from_seeds`, and that no import-shaped mention of `requests`, `socket`, `urlopen`, `http_probe`, `probe_endpoint`, `probe_lab_target` or `diff_check` appears. Importing it pulls in no HTTP client and no database driver, so it cannot probe or store even if it wanted to.
- ⚠️ **Dormant by design.** Nothing imports this module — it is not wired into the verifier, the summarizer, or any runner, and it makes no request and no write. Scope is decided by the caller's `authorize` callback (the same `Callable[[str], bool]` shape as `gateway.dns_pin.URLAuthorizer`), so this slice cannot widen authorization or the public-IP guard. It is an inventory *candidate list*, not a scan and not evidence: a candidate becomes a request only if a later, explicitly authorized probe asks for it.
- ✅ Committed as `ea17efa`: a base carrying userinfo (`https://user:pass@host`) is rejected in `_normalized_base`, with 9 cases covering it — the rejection happens before the authorizer is consulted at all, and an `@` after the first `/` is still treated as a path character. `tests/test_endpoint_inventory.py` is at 45 cases.
- ✅ `verification/endpoint_inventory_collector.py` — the live half, committed as `2f7fd55`. `collect_seed_inventory(base_url, authorize, session, asset_id, ...)` is the one place an inventory candidate can become a request: the whole seed list is authorized first (one out-of-scope URL ⇒ nothing is sent; a reject-everything authorizer ⇒ `[]` and zero requests), then exactly one guarded request per approved candidate — no retry, no redirect, no crawl, no concurrency — each stored via `store_inventory_evidence()` as an `endpoint_inventory` `Observation` with `hypothesis_id=None`, `flush()`ed but never committed. There is no header or credential parameter to pass, so no credential can be recorded, and only the audited probe allowlist reaches the row. Public targets use `probe_endpoint()`; the lab path requires `pin_lab_url()` plus `allow_private_network=True` and pins the entire candidate list *before* the first probe, so there is no second network path. Tests: `tests/test_endpoint_inventory_collector.py` (12 cases, including an AST import allowlist — no HTTP client, socket or subprocess is imported by the module).
- ✅ **Fail-closed is structural here too.** The collector has no `try`/`except`/`finally` anywhere, so an empty return can only mean "the authorizer approved nothing": a transport error, a refused target, a malformed base and an unknown asset all propagate, and a failed run cannot be mistaken for an empty inventory. The tests assert both halves — each propagation, and the absence of any handler (`ast.Try` walk, no `contextlib`, exactly one `return []`, which is the empty-candidate guard).
- ⚠️ **Inventory context is digest-bindable but never verdict-grade.** `verify_verdict()` refuses an `endpoint_inventory` row with `EVIDENCE_TYPE_MISMATCH`, `store_verdict()` raises before writing, and `promote_to_finding()` refuses it — three refusals locked in three different test files — and `intelligence/observation_summary.py` therefore renders such a row, its `url` included, as untrusted context rather than trusted scalars. `ARCHITECTURE.md` records that the trusted/untrusted split is keyed on the observation type.
- ⚠️ **Dormant and unrun.** Nothing imports the collector: no CLI, no scheduler, no caller in the suite, and no live run against the lab (which is down). Wiring it up or running it is a separate, deliberate operator decision; it is not a step the suite takes.

## DNS Pinning Review (completed)

Human review of the actual `gateway/dns_pin.py` contents (not just its passing tests), per the standing practice of distrusting green tests on security-sensitive modules. **Result: no exploitable defect found** — the SSRF/rebinding invariants hold. Verified properties:

- **Fail-closed ordering.** `pin_url()` validates the URL, calls `authorize(normalized_url)`, and only then resolves. An out-of-scope URL is rejected before any DNS query, so scope cannot be probed via resolution side effects.
- **Single parser, no differential.** The hostname derived once by `_parse_url()` is the same value used for authorization, resolution, the HTTP `Host` header, and the TLS server name. There is no second parser to disagree with, so authority-confusion tricks (`https://good.com\@evil.com/`, `user@host`, fragments such as `https://example.com#@evil.com/`) cannot redirect the request.
- **Strict answer validation.** *Every* resolved address must be `is_global`; a single private answer rejects the whole target, rather than filtering it out (which would permit rebinding onto the surviving private answer). Verified to cover IPv4 loopback, IPv6 loopback, IPv4-mapped loopback (`::ffff:127.0.0.1`), scoped link-local (`fe80::1%eth0`), link-local/metadata (`169.254.169.254`), carrier-grade NAT (`100.64.0.1`), and `0.0.0.0`. Public IPv6 answers are accepted.
- **No DNS-rebinding (TOCTOU) window.** The validated IP is carried in `PinnedTarget.addresses`; `verification/http_probe.py` connects to that literal IP (`create_connection((self._pinned_ip, self.port))`) with `max_retries=0`, and the URL is never re-resolved while `Host`/SNI stay bound to the hostname. The checked value and the used value are the same object.
- **Redirects are re-authorized.** `validate_redirect()` re-runs the full authorize + resolve + validate path on `urljoin(current, location)`, and the probe disables redirects entirely (`allow_redirects=False`).
- **Lab mode stays separate.** `pin_lab_url()` is the only path that skips the public-IP check; it still calls the authorizer, marks the target `is_lab_target=True`, requires `allow_private_network=True`, and is unreachable from public flows.

Documented, non-exploitable observations:

- The default port is not canonicalized in the `authorize()` input, so `https://example.com/` and `https://example.com:443/` are presented as different strings. This is fail-closed for exact-URL allowlists (the variant is rejected rather than widened) and is now locked in by `test_pin_url_does_not_canonicalize_the_default_port`.
- Authorization ultimately trusts the *resolved* address being global, so a caller-supplied `resolver` that returns a public IP for a non-canonical host (e.g. the decimal form `2130706433`) is trusted. The default `_system_resolver` is safe because `getaddrinfo` returns the numeric interpretation, which then fails the `is_global` check. Do not pass a permissive resolver.

`tests/test_dns_pin.py` grew 8 → 30 cases to pin the properties above so a future edit cannot silently weaken them.
